# 一维平板单群扩散特征值常驻后端

把"多区平板、裸板/外推/全反射边界、源迭代求 k_eff"的手算过程做成常驻 HTTP 服务：
工况可存可改、结果按参数版本留档、临界搜索异步执行、燃料燃耗历程分段推进。

- 内核：1D slab、单群、扩散方程 `-d/dx(D dφ/dx) + Σa φ = (1/k) νΣf φ`
- 离散：有限体积（守恒型），界面净流 `-D dφ/dx` 天然连续；**不在区界面上平均截面**
- 三对角求解（Thomas）、源迭代、二分求根全部手写；NumPy 仅用于数组运算
- 工况 / 参数版本 / 结果版本化持久化（卷挂目录即可保留）
- 临界搜索为异步作业，可查进度、可取消，作业锁定提交时刻的参数版本
- 燃耗历程挂在工况某一版参数上：恒定总裂变率下逐时间步推进，
  后台执行、可取消、可分段续算（含服务重启后），每个时间点单独留档

## 热启动策略（交付说明）

### 选了什么

- **初值**：把上一版收敛通量按新网格单元中心做**分段线性重映**
  （`interpolation.py`，手写），新坐标落在旧网格外用边界值外延；
  同时**继承上一版的 k**。热启动只继承形状不继承 k 时，右端 `(1/k)Fφ`
  与形状不匹配，实测反而比冷启动慢。
- **迭代**：热启动不用裸源迭代，而用 **Wielandt 逆移位（逆幂）加速**——
  每步取移位 `p = 1.01·k̂`（在当前 k 估计上方，使 `M−F/p` 正定、基模占优），
  解 `(M−F/p)ψ = Fφ`，归一后用广义 Rayleigh 商
  `k̂ = <Fψ,ψ>/<Mψ,ψ>` 重估 k。
  当改动很大、新 k 越过移位点（解出负值/非有限，或移位矩阵遇零主元）时，
  该步自动退回一杆普通源迭代，保证永远朝基模、永不出负通量。
- **判据**：k 与通量形状**两个都看**——
  `|Δk|/k < k_tol` 且 `‖φⁿ⁺¹−φⁿ‖₂/‖φⁿ⁺¹‖₂ < flux_tol` 才停。
  形状用归一化后的裂变源形状（即归一化通量本身）。

### 为什么这么选（真实取舍）

1. **为什么必须双判据，不能只看 k。** 源迭代里 k 比形状收敛快：
   形状里残留高阶模时，Rayleigh 型 k 更新可以先到位。只看 k 会"带着
   旧形状提前停下"，这正是热启动最容易踩的坑（旧通量本身就带着旧问题的
   形状偏差）。代价是每步多算一个 L2 差（O(M)，可忽略），多走若干步。
2. **为什么不用裸源迭代做热启动。** 平板扩散源迭代的形状收敛因子
   `ρ = λ₂/λ₁`（以 `M⁻¹F` 的特征值计）。基准裸板（a=50, D=1, Σa=0.1）
   ρ≈0.904，压到 1e-9 要 ~190 次形状更新；平坦冷启动因为高阶成分在
   前几步衰减快，常在 ~70 步过门，而热启动初值更"干净"、没有这部分
   快速衰减红利，逐次差又在 1e-10 舍入平台附近抖动，实测**更慢且不稳**。
   Wielandt 移位把高阶模比压到
   `(λ₂−λ₁)/(p−λ₁)` 量级，"改动越小、旧 k 越靠近新 k"时收益越大，
   正好契合"改某个区再算"的使用模式；它比 Chebyshev/多步外推简单、
   自校正、不会过头发散。
3. **判据松/严的权衡。** 双判据默认都取 1e-9：松到 1e-6 能再省几步，
   但冷热两条路径的 k 差就不再稳定地落在容差量级内、通量形状也会
   系统性差一截（被 `test_hot_cold` 抓到）；严到 1e-12 则逼近逐次差的
   舍入平台（~1e-10），步数虚高且残差抖动。1e-9 是这台问题上
   "结果可信"与"省步"的折中点；容差随工况可调。
4. **为什么是线性重映而不是外推几步再起步。** 改厚度/网格后，旧网格
   与新网格只是采样位置不同，线性重映得到的形状已经非常接近新基模；
   在旧解上做几步"外推加速"既依赖旧算子、又可能把旧问题的高阶误差
   放大，收益不稳。重映 + 移位逆幂这一组合对"改厚度/截面/加密"都鲁棒，
   大改动时退回普通迭代，结果始终与冷启动一致。

### 同一改动下冷、热两条路径的迭代次数（默认容差 1e-9，实测）

| 改动（在 a=50、100 网格的裸板上） | 冷启动 | 热启动 | k 之差 |
|---|---:|---:|---:|
| 厚度 50→52 cm、网格 100→120 | 75 | **9** | 2.6e-10 |
| 仅加密网格 50→100 | 70 | **4** | <1e-9 |
| νΣf 0.120→0.125 | 70 | **3** | <1e-9 |
| 大改：厚度 50→100、网格 100→200 | 228 | **17** | 2.9e-10 |

`pytest tests/test_hot_cold.py -s` 会打印这张表并断言冷热 k 差 <1e-7、
归一化通量形状差 <1e-6、两条路径中子平衡都 <1e-8。

## 燃耗（交付说明）

### 物理口径

- 燃料区可额外声明 `burnup`：易裂变核素初始数密度 `initial_density`
  （10²⁴/cm³）、微观吸收截面 `micro_sigma_a`（barn）、以及该区 Σa 中来自
  易裂变核素的份额 `fissile_absorption_fraction` ∈ [0,1]。
  未声明的区不燃耗，参数始终不变。
- 消耗速率 ∝ 当地通量 × 当地剩余数密度：`dN/dt = −σ_a^micro·φ·N`
  （σ 以 barn 计、φ 以 n/(cm²·s) 计、t 以秒计；接口时间步以天计）。
- νΣf 与 Σa 的易裂变部分按剩余份额 `s = N/N0` 同步缩小：
  `νΣf ← νΣf·s`，`Σa ← Σa·(1−f+f·s)`；Σa 其余部分与 D 不变。
- 全程恒定总裂变率：每个时刻通量都归一到所绑定版本的
  `target_total_fission`（这就是"功率旋钮"——要看到可观测燃耗，
  把它给到实际反应堆量级，如 1e14–1e16），燃料越烧通量幅值越高。
- 燃耗一开始消耗就是空间分辨的（中心快、边缘慢），剩余份额 s 逐单元
  存储、截面逐单元缩放；离散/求解器本来就工作在逐单元截面数组上，
  反应率仍是"逐单元截面积分按区求和"，统计口径不变，存储新增逐单元
  剩余份额。未声明燃耗的老工况、老结果原样可读，重解 k 逐位一致
  （数值内核零改动，`test_burnup.py` 与原有测试共同保证）。

### 时间积分格式：选了什么、为什么、代价是什么

**选了"步首冻结通量 + 步内解析指数积分"**（`depletion.deplete_step`）：
每个时间步里，用步首（上一时刻已归一的）通量 φⁿ 把耗散方程
`ds/dt = −σφⁿs` 解析积出 `s ← s·exp(−σφⁿΔt)`，再在新截面下热启动
求解该时刻的特征值。这是耦合系统 (φ, N) 的一阶分裂格式。

为什么选它而不是预估-校正或子步：

1. **不变量免费成立**。指数积分无条件保持 `s ∈ (0,1]`，通量非负性由
   求解器保证——验收要求的三条不变量（份额在 0 到 1、通量非负、k 单调
   下降）不会被大步长破坏；显式 Euler（`s ← s(1−σφΔt)`）在大步长下
   可能给出负的数密度，预估-校正也可能外推出界，都要额外裁剪。
2. **每步只花一次特征值求解**。燃耗的代价全在特征值求解上：
   预估-校正每步要 2 次求解换二阶精度，子步法按子步数成倍增加；
   教学场景下"把步长减半"比"每步多花一倍代价"更直观、更便宜。
3. **没有稳定性限制**。步内是解析解，大步长只损失精度、不会发散，
   学员可以放心试"一步 100 天"看趋势。

要付的代价：**全局一阶精度 O(Δt)**。冻结步首通量忽略了步内通量随
燃耗上升（恒定总裂变率下 φ·s 守恒、φ 随 s 下降而上升），系统性
低估消耗——s 与 k 略偏高（单边偏差）。要二阶精度就得上预估-校正
（每步两次求解）或子步（成倍代价），本版不实现。

**时间步减半时误差怎样缩小**：格式全局一阶，首项误差 ∝ Δt，
步长减半 → 偏差约减半。均匀全反射算例（k(t) 可手推，见下）实测：
10 天步长最大 k 偏差 3.6e-3，5 天步长 1.9e-3，比值 ≈ 1.95
（`pytest tests/test_burnup.py -s` 打印）。

### 均匀全反射手推参考（验收对照）

两端全反射的单区均匀板没有空间效应（B=0，通量恒平）。恒定总裂变率
F 下 `νΣf(t)·φ(t)·a = F` 即 φ·s 为常数，于是

```
ds/dt = −σ_a·φ·s = −σ_a·F/(νΣf0·a) = 常数
  ⇒  s(t) = 1 − σ_a·F·t/(νΣf0·a)        （剩余份额线性下降）
  ⇒  k(t) = νΣf0·s / (Σa0·(1−f) + Σa0·f·s)   （B=0 时 k = νΣf/Σa）
```

`physics.uniform_burnup_reference` 给出该参考；数值历程每个时间点
都要贴住它（见 `test_uniform_reflective_matches_hand_derived_and_halving`）。

### 历程、分段推进与确定性

- 一条历程在创建时锁定工况某一版参数的快照（可显式指定 `version`，
  缺省当前版）；工况随后被改、被删都不影响它。
- 每个已完成时间点单独落盘（k、通量、各区/逐单元剩余份额、各区反应率、
  两端泄漏、中子平衡残差 <1e-8），历程文档只记进度
  （已完成步数、当前燃耗时间、当前 k）与点索引。
- 分段推进：`max_steps` 控制本次推几步（停下为 `paused`）；取消为
  `cancelled`；服务重启时仍在跑的标 `interrupted`。三种状态以及
  `failed` 都可用 `POST /burnups/{id}/advance` 接着往后推。
- 续算从最后一个已落盘点的状态（逐单元 s、归一化通量、k）原样恢复：
  双精度浮点经 JSON 往返逐位不变，求解过程完全确定，因此
  "4 步 + 重启 + 6 步"与"一次推 10 步"逐点一致（实测 k 差为 0，
  剩余份额相对差为 0，远在"容差量级 / 1e-9"要求之内）。
- 取消只影响未完成的步：已完成的点全部保留。

## 离散与边界条件

单元中心有限体积。单元 `i` 宽 `h_i`，单元中心存 φ_i；
界面 `i±1/2` 上的净流用调和平均传导率表示，跨界面只用一次同一个流，
因此 `-D dφ/dx` 逐界面严格连续，界面两侧各自的 D、Σa 从不做平均：

```
J_{i+1/2} = g_{i+1/2}(φ_i − φ_{i+1/1})
g = 2 D_i D_{i+1} / (D_i h_{i+1} + D_{i+1} h_i)
```

同区等距时 `g = D/h`，退化成标准中心差分。

三种外边界（左右独立）：

| 边界 | 含义 | 边界面传导率 |
|---|---|---|
| `zero_flux` | 物理面上 φ=0（裸板） | `g_b = 2D/h`（镜像零值点） |
| `extrapolated` | 外推距离 `2.13 D` 处 φ=0 | `g_b = D/(h/2 + 2.13D)` |
| `reflective` | 全反射（对称面），J=0 | `g_b = 0` |

## 中子平衡

每次求解返回每区吸收率 `Σa φ h`、裂变率 `νΣf φ h`（以及单独的左、右端泄漏率），
并报告平衡残差：

```
rel_balance = | Σfission/k − Σabsorption − (J_left + J_right) | / (Σfission/k)
```

守恒型离散下这是望远镜求和恒等式，要求 `< 1e-8`（热启动同样要过）。

## 裸板加密与外推边界口径

多级网格（25/50/100/200/400）实测误差比约 4、收敛阶 ≈ 2（四种边界组合
都是）。要注意一个教学上常见的坑：外推边界在面元上的连续极限是
**Robin 条件** `J = Dφ/(2.13D)`（对应 `B tan(Ba/2)=1/d`），而教科书
`B = π/(a+2d)` 是小曲率近似。本服务的解析参考默认给与离散严格一致的
Robin 精确根（`physics.geometric_buckling(..., approximate=True)`
可取教科书近似）；对常用基准（Ba 很小）两者差 ~1e-4 量级。

## HTTP 接口（JSON）

工况：
- `POST /cases` 新建（物理校验不过返回 422，`details[].field` 逐字段指错）
- `GET /cases` / `GET /cases/{id}` 列表 / 查询
- `PATCH /cases/{id}` 改名或改某一区（除改名外生成新版本，非法改动被拒且不落版本）
- `DELETE /cases/{id}`
- `GET /cases/{id}/versions`
- `POST /cases/{id}/solve` body `{"mode":"cold"|"hot", "settings"?, "target_total_fission"?}`
  冷/热求解并存档；热启动自动取上一版最近的收敛通量+k；达到 max_iter
  未收敛返回 409，附 `iterations / k / k_residual / flux_residual`，不留结果。
- `GET /cases/{id}/results?version=` / `GET /results/{rid}`

临界搜索（异步）：
- `POST /cases/{id}/searches` body
  `{"region_index", "parameter":"thickness"|"nu_sigma_f", "lower","upper","max_steps"}`
  → 202 + 作业号。作业内嵌提交时刻的参数版本快照。
- `GET /jobs?case_id=` / `GET /jobs/{id}`：`status`（queued/running/
  converged/unconverged/rejected/cancelled/failed/interrupted）、
  `steps_taken`、`current_bracket`、`current_k`、`endpoint_k`、
  `root_value`、`k_at_root`、`result_id`。
- `POST /jobs/{id}/cancel`：置取消标志，工作线程在下一步评估前退出，
  终态 cancelled，不写结果。
- 两端 k−1 同号 → `rejected` 且回报 `endpoint_k`；
  收敛要求代回 |k−1| < 1e-6；步数耗尽 → `unconverged`，回报最后区间与残差。
- 同一工况可并发挂多个作业；工况随后被改/被删，作业仍只认提交时的版本，
  临界点解归档到该（被锁定的）版本下。

燃耗历程（异步）：
- `POST /cases/{id}/burnups` body
  `{"version"?, "steps":[天,...], "max_steps"?}` → 202 + 历程号。
  锁定所绑版本的参数快照；步长必须 > 0，步数 ≤ 500（否则 422 逐字段指错）。
- `GET /burnups?case_id=` / `GET /burnups/{id}`：`status`（running/paused/
  cancelled/interrupted/completed/failed）、`steps_completed`、
  `current_time_days`、`current_k`。
- `POST /burnups/{id}/advance` body `{"max_steps"?}`：接着往后推剩余步。
- `POST /burnups/{id}/cancel`：当前步完成后停下，已完成的点保留。
- `GET /burnups/{id}/points`：已完成时间点列表；
  `GET /burnups/{id}/points/{n}`：第 n 个时间点的完整留档
  （k、通量、各区/逐单元剩余份额、各区反应率、两端泄漏、中子平衡残差）。
- 同一工况的不同版本可同时各挂一条历程并发推进，各自的时间点互不混入。

## 持久化与容器

`DIFFUSION_DATA_DIR`（默认 `/data`）下 `cases/ results/ jobs/ burnups/
burnup_points/` 五个目录，每个对象一个 JSON 文件，临时文件 + `os.replace`
原子落盘，直接挂卷即可。
服务重启时仍在 queued/running 的作业标为 `interrupted`（不自动重跑，
避免参数语义漂移），其快照保留可查；仍在 running 的燃耗历程同样标为
`interrupted`，可从最后一个已落盘点继续推进。
